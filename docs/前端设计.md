## 一、全局框架（ProLayout）

```
┌───────────────────────────────────────────────────────────┐
│ ▣ 智能简历筛选系统  [处理任务 Badge]  [当前用户 / 角色 ▾] │ 顶栏
├──────────────┬────────────────────────────────────────────┤
│ 数据管理 ▾    │                                            │
│   · 简历库    │            内容区                          │
│   · 岗位需求  │      (ProTable / Modal 导入)              │
│   · 院校清单  │                                            │
│   · 部门接口人│                                            │
│ 系统设置 ▾    │  ← 接口人身份时，左侧仅保留「简历库」        │
│   · 配置项    │                                            │
│   · AI 模型连接│                                            │
│   · 用户权限  │                                            │
└──────────────┴────────────────────────────────────────────┘
```

> 当前结构：
> 1. **数据导入入口在各数据页内**：简历→简历库、岗位→岗位需求、院校→院校清单、接口人→部门接口人。
> 2. **处理由上传和处理简历触发**：两种入口都读取系统参数中的 AI 分配开关并只运行一种模式；关闭为 Rule，开启为 AI。“处理简历”只重算「简历分类、分配与下发」环节。
> 3. **所有数据表格支持列宽拖拽，可筛选业务列支持表头筛选**：可独立查询的列表采用后端分页，表头文本/单选/多选筛选参数进入接口查询，`page_size` 最大 500，导出全部按当前筛选条件执行；详情内嵌表格在当前详情数据内筛选。操作列可调整宽度但不提供筛选器。
> 4. **左侧菜单展开状态保持独立**：用户手动展开的一级菜单分组应保持展开；点击某个子页面只更新当前选中路由，不应自动收起其它已展开分组。
> 左侧菜单**按权限码和数据范围显示**：简历库是候选人查看、分配下发、二级转派和三级反馈的统一入口。HR/管理员查看全量；二级/三级接口人也进入 `/resumes`，但只看到本人接收或被转派的候选人和对应尝试。

当前共享实现：

- `DataTableControls.jsx` 提供服务端/本地文本筛选、单选/多选筛选、筛选参数规范化和可拖拽列宽 Hook；筛选浮层统一提供确认、重置和取消操作；简历库及其详情、岗位、院校、接口人、用户权限和各配置表统一复用。操作列允许调整宽度，但不添加筛选器。
- `ResizableTable.jsx` 为详情 Drawer 中的普通 Ant Design Table 接入同一列宽拖拽能力，并支持对当前详情数据执行本地表头筛选。
- `ResizableHeaderCell.jsx` 负责表头拖拽手柄和 pointer 事件；样式类 `.srf-column-resize-handle` 定义在全局 CSS。
- `ResumePreview.jsx` 负责 PDF/文件预览，PDF 通过鉴权 API 取得 Blob 后交给 PDF.js 渲染到 canvas，不依赖浏览器原生 PDF 内嵌能力；组件支持未选择、加载中、失败提示、分页、新窗口打开和“下载原文件”；可按 `resume` 直接预览，也可按 `attemptId` 走分配尝试数据范围预览。无权限或越权时不展示下载入口；PDF 渲染失败或非 PDF 文件时可下载原文件。
- 前端 API 封装位于 `src/api/services.js`：`previewResume`、`previewAllocationResume`、`exportCandidates`、`deleteCandidate` 分别对应预览、按筛选导出和候选人维护能力。
- 主布局提供非阻塞的“处理任务”顶栏按钮；仅 HR/管理员可见，Badge 约每 2 秒轮询并提示活跃数量。点击后打开非遮罩侧边 Drawer 任务中心，在其中查看每条运行的进度、任务耗时、范围摘要、结果、异常和取消审计。每张任务卡均直接使用运行 API 返回的 `elapsed_seconds` 格式化展示“任务耗时”，口径为从任务提交/创建到结束的总耗时，排队时间包含在内；排队、运行、等待冲突、取消中、已取消、成功、部分失败、失败和已撤销等所有状态均展示。尚无 `finished_at` 的任务耗时随约 2 秒轮询取得的新响应更新，写入 `finished_at` 后 API 返回固定值。任务中心提供「取消任务」：排队任务直接显示已取消；运行中/等待冲突任务显示取消中，完成安全停止后显示已取消，不回滚已生成结果。任务详情仅在 Drawer 中呈现。**目标设计（部分后端未实现）**：按各阶段累计工作量展示连续进度，并展示范围摘要、安全跳过、最近心跳和异常；心跳超时失败时明确展示原因，且仅未开始/等待冲突的范围项可由后端安全重试。不展示候选人 ID 范围明细。

### 1) 简历库（候选人列表 + 投递详情 + 上传即处理 + 撤销）

> **上传**：「上传简历」弹窗含两类文件 **① 简历信息列表 .xlsx / .xls / .csv + ② 简历包 .zip**。普通用户入口只提供安全的增量更新；主数据 replace 使用更新/停用语义，不得删除候选人流程、反馈或审计历史。测试环境彻底清空不放在普通上传弹窗中。
> **上传即处理**：上传含候选人数据时，后端读取全局 AI 分配开关并只创建一条当前模式运行；响应仍以 `processing_runs` 返回。生产异步环境提交后返回 202，本地 eager 模式同步完成后返回 200。任务编排 `Step1 查重与志愿排序 → Step2 简历分类、分配与下发`，不得复用 `all`。院校分类 Step3 和需求数据准备核对 Step4 是前置数据准备，可提前维护或独立运行；显式“全流程”才按 `Step3 → Step4 → Step1 → Step2` 执行。「处理简历」只提交带筛选范围的 Step2。发起按钮仅在提交请求期间禁用，拿到任务记录后页面仍可筛选、预览、下发、导出和跳转。
> **增量 + 冲突处理**：按 `normalized_name + normalized_phone` 归并候选人，按 `应聘ID` 幂等更新投递；低风险重复更新当前主记录，但不删除已反馈流程、分配尝试和历史快照；高风险重复进入导入错误清单。手机号缺失的候选人直接舍弃，不入库、不进入分配，并在导入结果中提示。
> **候选人聚合展示**：主列表以 `Candidate` 为行粒度，一名候选人只显示一行。HR/管理员详情展示手机号、最高学历专业、全部投递、志愿顺序、分配尝试、匹配/手动理由和反馈记录；接口人详情仅展示本人可见尝试及其关联投递，不返回手机号、其它志愿、其它尝试或 AI 决策。
> **当前志愿展示**：主列表仅展示当前有效志愿。初始只展示第一志愿；第一志愿反馈未通过后，系统生成并展示下一志愿；通过后固定展示通过志愿；归档后展示最后处理志愿和归档原因；当前志愿匹配岗位和二级部门但缺可用二级接口人时，固定展示当前志愿和阻塞原因。
> **简历状态**：简历库展示后端推导的统一状态，不覆盖导入文件中的原始“应聘状态”。状态选项为：待处理、已分类、已分配、待筛选、通过、不通过；内部状态码保持不变。存在历史不通过和下一志愿活动尝试时，按 `通过 > 待筛选 > 已分配 > 不通过 > 已分类 > 待处理` 展示，但只读取当前 workflow、当前通过指针和未取消活动尝试，历史 passed/rejected/cancelled 只在详情中展示，不覆盖重开后的当前状态。
> **主表列与筛选**：当前应聘ID保留在列设置中但默认隐藏，用户启用后可展示和筛选。主表删除流程状态、分配状态两列及对应表头筛选；流程状态、投递应聘状态和分配尝试状态继续在详情中展示并可在详情数据内筛选。原因列使用固定宽度截断，鼠标悬浮时通过 Tooltip 展示完整原因。
> **筛选、处理、下发与导出**：主列表支持现有候选人字段以及当前分配来源、部门、二三级接口人和分配原因的表头筛选，不提供流程状态或分配状态筛选。工具栏提供「处理简历」，弹窗只选择目标简历状态，并通过 `GET /api/allocation-mode/` 只读展示当前 Rule / AI 模式；`POST /api/pipeline/run/` 只提交 `step + scope`。HR 可单条、勾选批量或按当前筛选全部下发；批量接口只处理当前有效 `pending_dispatch` 尝试。该入口可按筛选范围重开流程并保留历史审计；导出继续按当前筛选结果执行。
> **简历预览与删除**：详情抽屉默认选中当前投递中有文件的简历；当前投递无文件时，自动回退到同候选人第一条有文件的投递，不改变当前志愿展示口径。候选人多条投递间可手动切换预览，未关联简历文件的投递预览入口置灰并提示原因；前端通过鉴权 API 获取 PDF Blob 后用 PDF.js 渲染到 canvas，并读取预览响应头 `X-Resume-Filename` 展示原始文件名。无权限或越权时不展示预览和下载入口；PDF 渲染失败或非 PDF 文件时可下载原文件。候选人存在分配尝试、反馈、AI 决策或转派历史时不显示可执行删除，或保持禁用并解释原因；后端返回 409 时展示原始错误说明。
> **按上传记录撤销（目标设计，后端未实现）**：后端先解析每次上传影响的业务键，只为该候选人/投递范围保存覆盖 Candidate / Resume / ResumeProfile / CandidateWorkflow / AgentDispatchDecision / AssignmentAttempt / AssignmentHandoff 的独立快照及本次上传关联处理完成后的流程版本基线；“上传撤销记录”只展示当前 HR 自己的上传，管理员可查看全部。用户按选定上传记录执行撤销，同一记录仅可撤销一次；撤销时后端锁定该记录的全部候选人并校验版本，任一候选人存在后续变更即整体返回 `409`，前端不显示部分撤销成功。关联 ProcessingRun 未结束时同样禁用该记录的撤销并展示原因；已撤销的运行保留审计展示。

### 2) 岗位需求 / 院校清单 / 部门接口人（结构同构）
```
岗位需求                                       [↥ 导入岗位] [新增岗位]
│ 对外名称│职位名称│岗位类别│岗位族│部门│工作地│学历│HC│对外发布│操作
│ ...    │...   │...   │... │...│...│...│...│...    │编辑 删除

院校清单                                       [↥ 导入院校]
│ 学校 │ 院校标签 │

部门接口人                                     [↥ 导入接口人]
│ 姓名 │ 工号 │ 所属部门 │ 部门层级 │ 接口人层级 │ 可转派
```
> 三页各自只导入对应的一张表格文件（.xlsx / .xls / .csv）；后端复用同一 `/api/import/`（按字段区分），无需分别建接口。
> 岗位、院校、部门接口人列表均使用表头筛选和列宽拖拽；筛选条件进入后端查询并与分页共同生效。岗位支持主体、发布名称、岗位族、部门、地点、学历、HC、是否发布等筛选，并提供编辑和删除操作；删除岗位采用停用/失效语义，历史投递和分配尝试仍可追溯。院校清单前端只展示学校和院校标签，不展示所在地/所在省份；省份字段可作为导入和排序规则后台数据保留。接口人支持姓名、工号、部门、层级、是否可转派、是否启用筛选；不展示或筛选招聘主体归属/主体来源。
> 部门接口人 replace/清空重导时，本次文件中不存在的旧接口人及其绑定账号会同步停用；列表默认只展示启用接口人，可通过状态筛选查看停用接口人。单条“删除”操作采用清理语义：删除接口人并同步删除绑定用户，历史分配记录不删除，只通过快照字段展示原接口人信息。
> **字典化口径**：岗位类别来自 `JobCategory` 字典，院校标签来自 `SchoolTag` 字典，专业大类词表来自 `MajorCategory` + `MajorAlias`；字典项保留 `code + name` 或规范化名称，前端展示业务名称，导入/匹配优先使用 `code` 或规范化名称。
> **非目标院校预置**：院校标签字典预置启用 `NON_TARGET / 非目标院校`。院校清单外的学校在分类时始终写入该标签；清单内学校未配置标签时才使用启用默认标签，无默认标签时回退到该预置标签。院校列表可显示/维护清单内学校的标签，但不能把清单外学校误展示为默认标签。
> **院校标签准入规则**：配置项中维护 `SchoolTagRule`，规则允许标签通过 `SchoolTagRuleTag` 关联到 `SchoolTag`，并区分第一学历/最高学历两个作用域。
> **招聘主体**：岗位和投递引用 `RecruitingEntity.code`，前端直接展示 GW / YLS 等主体编码；部门和部门接口人不建立“属于招聘主体”的关系。
> **省份口径**：`School` 只保存所在省份 `province`；系统不维护南北省份分区字典，南北归属仅在志愿排序规则运行时计算，不落库、不作为配置页维护项。

### 3) 候选人处理主流程（随上传/处理简历提交后台任务）
处理由两个动作触发，均创建**可共享的后台任务**：
- **上传简历**（简历库）→ 按全局 AI 分配开关创建当前唯一模式运行；
- **处理简历**（简历库）→ 按相同全局模式创建运行，只重算「简历分类、分配与下发」环节。

> AI 模式通过真实模型链路处理；未配置密钥或调用失败时展示后端失败原因和处置入口，不得展示 Rule 结果、固定置信度或元数据拼接结论。

```
前置数据准备：
  院校分类、需求录入、部门接口人维护

候选人处理主流程：
  Step1 查重与志愿排序 → Step2 简历分类、分配与下发
```
> 院校分类和需求录入提前完成，保证分配时院校标签、岗位需求、专业要求和接口人已就绪。
> 前端提交 `/api/pipeline/run/` 或上传请求后，生产异步环境收到 `202 + processing_runs` 即恢复页面操作；本地 eager 模式同步完成后返回相同字段的 200。每次只创建当前全局模式的一条运行。HR/管理员通过顶栏「处理任务」Badge 与非遮罩侧边 Drawer 约每 2 秒轮询；二级、三级接口人不展示任务中心。任务切换开关后仍按提交时固化的模式继续执行。
> 多个 HR 可同时提交任务。提交范围与版本快照已由后端固化；同一候选人的自动任务会等待当前候选人事务完成。**目标设计（后端未实现）**：人工下发、转派、反馈或手动分配与自动任务使用统一流程锁，版本不一致时任务显示 `skipped_manual_change` 安全跳过结果，不覆盖人工操作。

### 4) 简历库中的分配尝试
```
简历库                                [处理简历] [下发选中] [一键全部下发]
┌ 表头筛选: 来源、部门、接口人、候选人、投递岗位、分配原因
├──────────────────────────────────────────────────────────
│候选人│岗位│来源│二级接口人│三级接口人│分配原因（截断）│操作│
│张三  │后端│规则│技术部接口人│平台组接口人│岗位与专业匹配… │查看│
└ 详情展示全部投递、历史尝试、AI 决策、反馈和简历预览
```
> **统一操作台**：简历库主表展示当前有效 `AssignmentAttempt` 的业务结果，但不展示分配状态；详情展示完整历史及每次尝试状态。HR 进行待复核确认、取消、转人工、单条/选中/筛选全部下发；二级接口人转派；三级接口人反馈。分配原因统一读取 `match_reason`，主表截断显示并支持悬浮查看全文，Rule 和 AI 来源都保留审计。
> **AI 决策边界**：失败、低置信度和建议归档而未生成尝试的 AI 决策保存在简历库详情；AI 开关关闭时“重试 AI”禁用，但历史决策仍可查看，已有待复核建议仍可确认、取消或转人工，已有待下发尝试仍可下发。
> **Rule 策略**：按志愿顺序、院校标签准入规则、招聘主体一致性、岗位需求映射、岗位需求专业、岗位二级部门和二级接口人生成待下发尝试；岗位未配置需求专业，或岗位需求专业为“专业不限 / 不限 / 不限专业”等通配表达时，不阻断自动分配。岗位配置非通配需求专业时，后端先用专业大类词表判断候选人最高学历专业与岗位需求专业是否同属大类；若大类无交集，或候选人/岗位任一侧未映射到启用大类，则再用专业名双向包含兜底。当前志愿匹配岗位和二级部门但缺可用二级接口人时，前端不展示下一志愿，而是在简历库显示阻塞原因。多岗位命中时后端按同主体、精确匹配、对外发布名称、职位名称和包含匹配的固定顺序选择岗位，并在尝试详情展示岗位、专业大类/专业名、部门和接口人等匹配理由。
> **AI 策略（当前实现）**：Agent 只处理候选人的当前有效志愿，硬规则先行，不跨志愿跳转。后端先定向查询可能匹配当前志愿的启用岗位，再按招聘主体、岗位名命中级别和 `job.id` 兜底排序稳定选出一个目标岗位；该目标不是数据库天然唯一记录。随后 Agent 读取 `ResumeProfile.raw_text` 及结构化画像字段，结合仅含该目标岗位需求专业、二级部门和有效二级接口人的 `current_job` 上下文判断适配性，不包含或推荐其它岗位。当前志愿无匹配启用岗位时不调用模型，前端沿用现有 AI 失败决策和归档展示，不新增接口或交互。达到 `ai_dispatch_threshold` 形成 `pending_dispatch`；达到 `ai_review_threshold` 但未达到自动下发条件时形成 `pending_review`；建议归档、低于复核阈值、简历缺失、解析失败或最终失败时只展示 AI 决策，不生成分配尝试，候选人流程显示为“已归档 / AI 无有效建议”。前端轮询 `ProcessingRun` 展示进度；`partial_failed` 显示警告，不提示完全成功。
> **分配尝试**：简历库主表支持来源、部门、接口人、候选人、投递岗位和分配原因筛选，不展示或筛选分配状态；详情保留尝试状态筛选，并支持导出、下发、转派、反馈、查看详情和简历预览。接口人只看到本人数据范围内已下发或已转派的尝试，不展示 HR 待处理状态。
> **AI 复核操作**：HR 可在 `pending_review` 尝试详情中确认下发、取消或转人工处理；AI 开关开启且当前连接测试有效时还可重试 AI。分别调用 `confirm-review`、`cancel-review`、`transfer-to-manual` 和 AgentDecision `retry` 接口。取消后若没有其它活动尝试，简历库显示 `agent_no_recommendation` 归档；转人工时必须从该尝试的具体投递进入手动分配，不允许隐式换志愿。
> **待下发取消**：HR 可取消 `pending_dispatch` 尝试，调用 `POST /api/workflow-attempts/{id}/cancel/`；取消后刷新候选人当前状态和可执行操作。
> **AI 失败边界**：AI 超时、调用失败、PDF 解析失败、输出不合法、推荐对象不存在或被硬规则拦截时，不自动回退 Rule；前端提示失败原因。AI 开关开启且连接仍有效时允许重试；关闭开关后可按 Rule 重新处理，手动强制分配始终可用。
> **详情与预览**：分配尝试详情抽屉展示候选人、应聘ID、岗位、二级/三级接口人、状态、反馈备注等信息，并通过 `/api/workflow-attempts/{id}/resume-preview/` 在当前用户数据范围内获取 PDF Blob，再用 PDF.js 渲染到 canvas。接口人账号只能预览自己可见分配尝试的简历；越权尝试由后端返回 404/403 类错误，前端展示为不可预览且不提供下载入口。PDF 渲染失败或非 PDF 文件时，保留下载原文件入口。
> **导出**：导出候选人**简历文件**（`/api/workflow-attempts/export/`）；支持单条、勾选批量、按筛选「导出全部」。单条且命中一个可用文件、没有缺失清单时直接下载原文件；批量、多文件或存在缺失清单时下载 zip，缺失候选人写入压缩包内「缺失简历文件清单.txt」。前端读取 `X-Export-Count` / `X-Export-Missing` 展示导出统计。
> **HR 下发操作**：HR 可单条下发，也可勾选多条后「下发选中」，或按当前简历库筛选条件「一键全部下发」。候选人维度批量接口只处理当前有效 `pending_dispatch` 尝试，其他状态自动跳过并提示成功/跳过数量。
> **下发、转派与反馈**：HR 将待下发尝试下发至二级部门接口人；二级接口人在本二级部门范围内选择三级部门接口人并转派；三级接口人对已转派尝试提交通过/未通过 + 可选备注，提交后锁定。
> **转派操作**：二级接口人在简历库本人可见候选人行或详情中使用「转派」，弹窗只列出当前二级部门下启用的三级接口人；转派后状态变为「已转派三级」，并记录转派历史。
> **手动强制分配**：HR 从具体应聘ID打开弹窗，先选择目标类型（二级接口人 / 三级接口人），再选择对应接口人。选择二级接口人时走普通下发与二级转派链路；直接选择三级接口人时，前端展示其父级二级部门：若只有一个有效二级接口人则自动补齐，若有多个则要求 HR 明确选择，确认后进入「已转派三级 / 待反馈」并展示两段转派历史。没有有效父级二级接口人时阻止提交并提示改选二级接口人。已通过候选人不可通过该入口再次强制分配；如需重开已通过候选人，使用简历库「处理简历」入口。
> **归档候选人**：归档原因、志愿概览和从具体应聘ID发起手动强制分配统一合并到简历库；不再作为 HR 独立菜单入口。
> **角色差异**：二级接口人仅看到已下发给自己的尝试，可导出、查看反馈和转派给本部门三级接口人；三级接口人仅看到转派给自己的尝试，可导出并提交反馈；接口人均无 HR 下发、手动分配、二级接口人筛选和模式开关。

### 5) 业务配置与系统设置（设计 · M4/M6）
- **配置项**：系统参数新增 `ai_enabled` AI 分配开关，默认关闭；关闭只运行 Rule，开启只运行 AI。另包含 AI 阈值、超时、并发、重试、任务心跳超时等参数。开启 AI 时后端要求当前模型连接已经测试成功，页面展示拒绝原因。
- **AI 模型连接**：系统设置提供独立的「AI 模型连接」子页（路由 `/ai-connection`），使用 `GET/PATCH /api/ai-connection/` 配置 profile、`api_style`、模型名、Base URL 和 API Key，并提供真实连接测试。连接状态展示当前配置是否测试通过和测试时间；保存或清除任何连接配置会使测试状态失效并自动关闭 AI 开关。Key 绝不回显。该页由 `settings.manage_ai_connection` 控制。
- **准入规则配置**：规则表单从 `SchoolTag` 字典勾选标签，保存为 `SchoolTagRule` + `SchoolTagRuleTag`；第一学历允许标签和最高学历允许标签分开配置，但候选人必须在同一条启用规则内同时命中第一学历和最高学历标签才算通过；多条启用规则之间 OR，没有启用规则时视为不做院校准入过滤。
- **专业大类词表配置**：配置项新增「专业大类词表」页签。页面展示专业大类列表和当前大类下的专业别名/关键词，支持新增、编辑、停用、删除；字段包括大类编码、大类名称、大类说明、排序、专业别名、匹配方式（精确 / 包含）、来源、备注和启用状态。内置词表可编辑和停用；专业大类存在任何别名时不允许直接删除，确需删除需先删除或迁移别名，后端返回明确错误时前端以消息提示。
- **用户权限**：RBAC 配置页，管理员维护用户、角色、权限绑定和接口人绑定关系；接口人账号由部门接口人导入自动创建，用户管理不单独维护 `first_name`、`last_name` 等 Django 姓名类字段，并支持删除用户。

> 权限分区：岗位类别、院校标签、院校准入规则、专业大类词表和 AI 非敏感运行参数属于业务配置，可分别授权 HR/管理员；用户、角色、权限、认证和安全开关属于系统设置。AI 模型连接使用独立的 `settings.manage_ai_connection` 权限，默认授予管理员角色，管理员可按角色委派。前端按具体权限码控制菜单、路由和页面，不以“是否管理员”硬编码整个配置页。
> 普通配置页通过 `GET /api/configs/` 获取白名单项，通过 `PATCH /api/configs/{key}/` 更新；未知配置、类型错误或越权由后端拒绝。AI 连接使用独立且受 `settings.manage_ai_connection` 保护的接口，不在普通配置列表混入或回显 Key；前端不提供任意新增/删除配置键。

用户权限页建议拆成三个页签：

| 页签 | 主要能力 | 说明 |
| ---- | -------- | ---- |
| 用户管理 | 用户列表、新增/编辑/启停/删除用户、绑定角色、绑定接口人 | 接口人用户由导入自动创建，用户名为工号；用户管理不展示/编辑 `first_name`、`last_name` 等姓名类字段，接口人姓名来自绑定 `Contact`；导入同步接口人角色时保留其它业务角色；删除用户采用账号清理语义，删除账号、Token 和角色绑定，若用户绑定接口人则同步删除接口人；历史审计和分配记录不删除，只保留快照展示；二级/三级数据范围由绑定接口人和部门关系决定 |
| 角色管理 | 角色列表、新增、编辑角色 | 预置 HR、二级接口人、三级接口人、管理员；管理员可按需新增业务角色；Django Group 暂不提供独立启停状态 |
| 权限配置 | 以树形权限点为角色勾选授权 | 权限点由后端预置，只允许勾选绑定，不允许前端随意新增未知权限码 |

权限树按模块组织：

| 模块 | 权限示例 |
| ---- | -------- |
| 简历库 | 查看、上传、撤销、导出、手动分配 |
| 主数据 | 岗位需求、院校清单、部门接口人的查看/导入/编辑/删除 |
| 分配工作流 | 查看工作流、查看尝试、单条下发、批量下发、一键全部下发、导出 |
| 接口人处理 | 二级转派、三级反馈、反馈查看 |
| 业务配置 | 岗位/院校字典、准入规则、专业词表、AI 非敏感运行参数 |
| 系统设置 | 用户权限、认证与安全配置、AI 模型连接（`settings.manage_ai_connection`） |

前端权限生效：
- 登录后调用 `/api/me/`，获得 `permissions`、`roles`、`contact`、`data_scope`。
- ProLayout 菜单按权限码过滤；页面按钮按权限码控制显示和禁用态。菜单的展开分组由前端显式维护，路由跳转和子页选择只影响选中态，不清空其它已展开分组。
- 无权限路由展示「无权限」页面；接口请求失败仍以后端 403 为准。
- 本地开发阶段使用系统账号密码登录并保存 Token；接口人账号用户名为工号，新账号默认密码为 `pass1234`；W3 认证接入后按工号识别用户并替换登录适配层，页面仍消费 `/api/me/`。

## 三、角色与可见性

权限体系采用 RBAC。前端不再写死角色能力，而是基于 `/api/me/` 返回的权限码、角色、接口人绑定和数据范围动态控制菜单、路由和按钮：

| 区域 | 默认角色权限 | 二级接口人 | 三级接口人 |
|------|-------------|------------|------------|
| 简历库 — 候选人列表和本人分配数据 | 全量 | 仅本人接收 | 仅本人被转派 |
| 简历库 — 上传 / 撤销 / 删除 / 处理简历 | ✓ | ✗ | ✗ |
| 简历库 — 导出 / 反馈查看 | ✓ | ✓（本人范围） | ✓（本人范围） |
| 简历库 — 单条/批量/全部下发 / 手动强制分配 | ✓ | ✗ | ✗ |
| 分配尝试 — 转派给三级接口人 | ✗ | ✓ | ✗ |
| 分配尝试 — 提交通过/未通过反馈 | ✗ | ✗ | ✓ |
| AI 模型连接 — 查看/保存/测试 | 拥有 `settings.manage_ai_connection` 的角色（管理员默认拥有） | 未授予时 ✗ | 未授予时 ✗ |
| 业务规则配置 | 按权限码授权 HR / 管理员 | ✗ | ✗ |
| 用户权限与安全设置 | ✓（管理员）| ✗ | ✗ |

> 二级/三级接口人登录后默认落到「简历库」。接口人响应不包含手机号、其它志愿、其它尝试或 AI 决策，简历预览和导出使用尝试级数据范围。
> **重要边界**：前端权限配置只负责体验和误操作拦截，不能替代后端鉴权。后端接口必须同步按权限码鉴权，并保证“二级只能看自己接收且已下发的尝试并只能转派本部门三级接口人”“三级只能看自己被转派的尝试”。

## 四、目标页面清单与当前状态
1. 简历库：统一承载候选人列表、当前分配结果、分配原因、AI 复核、HR 单条/批量/筛选全部下发、二级转派、三级反馈、详情、历史尝试、AI 决策和简历预览。主表不展示流程状态或分配状态，当前应聘ID默认隐藏，原因截断并支持悬浮查看全文；处理弹窗只选择简历状态并展示当前全局模式。上传和处理都只生成当前模式的一条任务。HR/管理员看全量，接口人只看本人范围。
2. 岗位需求、院校清单、部门接口人：主数据维护、导入、表头筛选和列宽拖拽；岗位需求支持编辑和删除；院校清单前端不展示所在地。
3. 配置项：系统参数维护 `ai_enabled`、AI 阈值、超时并发重试等参数；拥有 `settings.manage_ai_connection` 的角色另有独立「AI 模型连接」页，连接测试成功后才能开启 AI。
4. 用户权限：维护用户、角色、权限绑定和接口人绑定关系，支撑 RBAC 前端配置。
