```

├──────────────┬────────────────────────────────────────────┤
│ 数据管理 ▾    │                                            │
│   · 简历库    │            内容区                          │
│   · 岗位需求  │      (ProTable / Modal 导入)              │
│   · 院校清单  │                                            │
│   · 部门接口人│                                            │

│   · 分配尝试  │                                            │
│   · 归档候选人│                                            │
│ 系统设置 ▾    │  ← 接口人身份时，左侧仅保留「简历分配」      │

└──────────────┴────────────────────────────────────────────┘

> 当前结构：
> 1. **数据导入入口在各数据页内**：简历→简历库、岗位→岗位需求、院校→院校清单、接口人→部门接口人。
> 2. **处理由上传和策略切换触发**：上传简历后自动触发候选人处理主流程；分配页切换 Rule / AI 分配策略时，只重算「简历分类、分配与下发」环节。
> 左侧菜单**按权限码和数据范围显示**：HR/管理员按授权菜单进入业务与设置页面；二级/三级接口人仅见与其数据范围匹配的「分配尝试」。**分配策略**位于分配工作流区域，分配页是其结果落点。

## 二、关键页面

### 1) 简历库（候选人列表 + 投递详情 + 上传即处理 + 撤销）
```
简历库                    [↥ 上传简历] [↺ 撤销上次上传] [导出]
┌ 筛选: 导入时间[范围] 状态[▾] 🔍姓名/手机
├──────────────────────────────────────────────────────────
│ 姓名 │手机│当前志愿│当前投递岗位│岗位类别│院校标签│流程状态│操作
│ 张三 │138│1       │后端        │技术类  │平台A   │进行中  │详情 手动分配
│ 李四 │139│1       │产品        │产品类  │平台B   │待分配  │详情
└ 分页 / 共 N 名候选人

详情抽屉 / 详情页：
┌ 候选人：张三  13800000000  院校标签：第一学历=平台A / 最高学历=平台A
├ 投递志愿
│ 志愿│应聘ID│主体│投递岗位│岗位类别│应聘状态│分配状态│反馈
│ 1  │A001 │GW │后端    │技术类  │待处理  │已转派三级│未通过
│ 2  │A002 │YLS│产品    │产品类  │待处理  │待下发  │-
├ 分配尝试
│ 次序│来源│投递岗位│二级接口人│三级接口人│状态│反馈备注│时间
└ 操作：从选中应聘ID发起手动强制分配（目标可选二级接口人或三级接口人）

上传后自动弹出进度条：
┌ 正在处理简历（分配策略：Rule） ───────────────  ┐
│ [■■■■■■□□□□] 60%   正在：简历分类、分配与下发   │
└────────────────────────────────────────────────┘

> **上传**：「上传简历」弹窗含两类文件 **① 简历信息列表 .xlsx / .xls / .csv + ② 简历包 .zip** + 导入模式（增量/清空重导）。
> **上传即处理**：上传成功后自动按当前分配策略跑候选人处理主流程（查重与志愿排序 → 简历分类、分配与下发），前端按环节驱动进度条。院校分类和需求录入是前置数据准备，可在对应主数据页提前维护或独立重跑。
> **增量 + 冲突处理**：按 `normalized_name + normalized_phone` 归并候选人，按 `应聘ID` 幂等更新投递；低风险重复更新当前主记录，但不删除已反馈流程、分配尝试和历史快照；高风险重复进入导入错误清单。手机号缺失的候选人直接舍弃，不入库、不进入分配，并在导入结果中提示。
> **候选人聚合展示**：主列表以 `Candidate` 为行粒度，一名候选人只显示一行；所有投递岗位、应聘ID、志愿顺序、分配尝试和反馈记录进入详情抽屉/详情页。
> **当前志愿展示**：主列表仅展示当前有效志愿。初始只展示第一志愿；第一志愿反馈未通过后，系统生成并展示下一志愿；通过后固定展示通过志愿；归档后展示最后处理志愿和归档原因。
> **单级撤销**：上传前后端存一份快照（Candidate/Resume/CandidateWorkflow/AssignmentAttempt）；「撤销上次上传」一键回到上传前状态（删本次新增 + 还原被覆盖旧值），撤销后快照清除。仅保留最近一次（单级）。

### 2) 岗位需求 / 院校清单 / 部门接口人（结构同构）
```
岗位需求                                       [↥ 导入岗位]
│ 对外名称│职位名称│岗位类别│岗位族│部门│工作地│学历│HC│对外发布│

院校清单                                       [↥ 导入院校]
│ 学校 │ 院校标签 │ 所在省份 │

部门接口人                                     [↥ 导入接口人]
│ 姓名 │ 工号 │ 所属部门 │ 部门层级 │ 接口人层级 │ 可转派
```
> 三页各自只导入对应的一张表格文件（.xlsx / .xls / .csv）；后端复用同一 `/api/import/`（按字段区分），无需分别建接口。
> 部门接口人 replace/清空重导时，本次文件中不存在的旧接口人及其绑定账号会同步停用；前端导入结果需保留成功/跳过/错误提示，避免误以为旧账号仍可登录。
> **字典化口径**：岗位类别来自 `JobCategory` 字典，院校标签来自 `SchoolTag` 字典；两类字典项均保留 `code + name`，前端展示 `name`，导入/匹配优先使用 `code` 或规范化名称。
> **院校标签准入规则**：配置项中维护 `SchoolTagRule`，规则允许标签通过 `SchoolTagRuleTag` 关联到 `SchoolTag`，并区分第一学历/最高学历两个作用域。
> **招聘主体**：岗位和投递引用 `RecruitingEntity.code`，前端直接展示 GW / YLS 等主体编码；部门和部门接口人不建立“属于招聘主体”的关系。
> **省份口径**：`School` 只保存所在省份 `province`；系统不维护南北省份字典或 `ProvinceRegion`，南北归属仅在志愿排序规则运行时计算，不落库、不作为配置页维护项。

### 3) 候选人处理主流程（随上传/换策略自动触发）
处理由两个动作触发，均以**进度条**呈现：
- **上传简历**（简历库）→ 自动跑候选人处理主流程；
- **切换 Rule / AI 分配策略**（简历分配页）→ 只重算「简历分类、分配与下发」环节。

```
前置数据准备：
  院校分类、需求录入、部门接口人维护

候选人处理主流程：
  Step1 查重与志愿排序 → Step2 简历分类、分配与下发
```
> 院校分类和需求录入提前完成，保证分配时院校标签、岗位需求、专业要求和接口人已就绪。
> 前端逐步调用 `/api/pipeline/run/` 推进进度条；后端同步/异步执行方式和 `ProcessingRun` 记录口径见 `docs/后端设计.md`。

### 5) 分配工作流 / 分配尝试 / 归档候选人
```
候选人工作流                    分配策略: ( Rule ) ( AI )
                              [运行分配]
┌ 筛选: 状态[▾] 候选人 投递岗位
├──────────────────────────────────────────────────────────
│候选人│当前志愿│当前投递│策略│流程状态│归档原因│更新时间│操作       │
│张三  │1       │后端    │AI  │进行中  │        │09:30   │查看尝试   │
└ 已归档候选人可从具体应聘ID发起手动强制分配（目标可选二级/三级接口人）
```
> **分配策略**：页头提供一个分段器「Rule / AI」。切换前先弹确认；确认后只重算「简历分类、分配与下发」环节。选择存于前端（localStorage），上传简历时也读取当前选择。
> **Rule 策略**：按志愿顺序、院校标签准入规则、岗位需求映射、岗位二级部门和二级接口人生成待下发尝试。
> **AI 策略**：Agent 只处理候选人的当前有效志愿，硬规则先行，不跨志愿跳转。Agent 读取 PDF 简历解析出的 `raw_text` / `ResumeProfile` 和项目经历，结合当前志愿、岗位需求专业与部门信息完成岗位分类、适配判断和二级部门/二级接口人推荐。`recommendation=dispatch` 且 `confidence_score >= 0.75` 形成 `pending_dispatch` 待下发尝试；`recommendation != archive` 且 `confidence_score >= 0.5` 但未达到自动下发条件时，形成 `source=ai, pending_review` HR 复核项，不直接下发；HR 确认后转为 `pending_dispatch`；`recommendation=archive`、`confidence_score < 0.5`、简历缺失或 PDF 解析失败时只展示 AI 决策记录并建议归档或人工处理，不生成分配尝试。AI 运行期间，列表可边跑边显示已处理、待下发、待复核、失败和建议归档数量；部分失败时展示 `partial_failed` 状态和失败数量。
> **分配尝试**：展示 `AssignmentAttempt`，支持状态筛选、导出、下发、查看反馈。接口：`/api/workflow-attempts/`。
> **AI 复核操作**：HR 可在 `pending_review` 尝试详情中确认下发、取消、转人工处理或重试 AI；确认后该尝试进入 `pending_dispatch`，再走普通 HR 下发流程。
> **AI 失败边界**：AI 超时、调用失败、PDF 解析失败、输出不合法、推荐对象不存在或被硬规则拦截时，不自动回退 Rule；前端提示失败原因，由 HR 明确选择重试 AI、切换 Rule 或手动强制分配。
> **AI 决策详情**：HR 可在尝试详情查看 AI 推荐动作、推荐岗位/岗位类别/二级部门/二级接口人、总置信度、分项评分、推荐理由、简历证据和风险点。系统不保存完整 LLM 原始响应；接口人只看到已下发给自己的尝试和必要简历信息。
> **AI 决策列表**：展示所有 AI 决策，包括未生成 `AssignmentAttempt` 的失败、低置信度和建议归档记录；HR 可在该列表或归档候选人详情中重试 AI、切换 Rule 或发起手动强制分配。重试接口：`POST /api/agent-decisions/{id}/retry/`。
> **导出**：把候选人**简历文件**打包成 zip 下载（`/api/workflow-attempts/export/`）；支持单条、勾选批量、按筛选「导出全部」。无文件的候选人写入压缩包内「缺失简历文件清单.txt」。
> **HR 下发操作**：HR 可单条下发，也可勾选多条后「下发选中」，或按当前筛选条件「一键全部下发」。批量下发只处理 `pending_dispatch`，其他状态自动跳过并提示成功/跳过数量。接口：`POST /api/workflow-attempts/bulk-dispatch/`。
> **下发、转派与反馈**：HR 将待下发尝试下发至二级部门接口人；二级接口人在本二级部门范围内选择三级部门接口人并转派；三级接口人对已转派尝试提交通过/未通过 + 可选备注，提交后锁定。
> **转派操作**：二级接口人的分配尝试列表展示「转派」按钮，弹窗只列出当前二级部门下启用的三级接口人；转派后状态变为「已转派三级」，并记录转派历史。
> **手动强制分配**：HR 从具体应聘ID打开弹窗，先选择目标类型（二级接口人 / 三级接口人），再选择对应接口人。选择二级接口人时走普通下发与二级转派链路；直接选择三级接口人时尝试进入「已转派三级 / 待反馈」状态，并展示对应转派历史。
> **归档候选人**：独立页面展示归档原因、志愿概览，并允许 HR 从具体应聘ID发起手动强制分配。
> **角色差异**：二级接口人仅看到下发给自己的尝试，可导出、查看反馈和转派给本部门三级接口人；三级接口人仅看到转派给自己的尝试，可导出并提交反馈；接口人均无 HR 下发、手动分配和模式开关。

AI 决策详情建议布局：

| 区域 | 展示内容 |
| ---- | -------- |
| 推荐结论 | 推荐动作、推荐岗位、岗位类别、二级部门、二级接口人 |
| 置信度 | 总分 + 专业匹配、技能匹配、项目/实习证据、岗位需求覆盖、部门确定性、简历质量分项 |
| 业务理由 | 一句话摘要、推荐理由 |

| 风险点 | 解析失败、文本过短、项目不足、专业不明确、推荐对象不存在等提示 |
| 操作 | 确认下发、取消、转人工处理、重试 AI |

### 6) 系统设置（设计 · M4/M6）
- **配置项**：岗位类别字典、院校标签字典、院校标签准入规则、`ai_dispatch_threshold`（默认 0.75）、`ai_review_threshold`（默认 0.5）、AI 超时、AI 并发、AI 重试次数、AI 重试退避、W3 认证开关；不维护南北省份字典。
- **AI 连接配置边界**：前端配置页只维护阈值、超时、并发、重试次数和退避等非敏感运行参数；大模型供应商、模型名、API Key 环境变量名、Base URL 环境变量名、提示词版本和决策版本由后端配置文件读取环境变量管理。前端不展示、不编辑、不接收真实 API Key。
- **准入规则配置**：规则表单从 `SchoolTag` 字典勾选标签，保存为 `SchoolTagRule` + `SchoolTagRuleTag`；第一学历允许标签和最高学历允许标签分开配置，但候选人必须在同一条启用规则内同时命中第一学历和最高学历标签才算通过；多条启用规则之间 OR，没有启用规则时视为不做院校准入过滤。
- **用户权限**：RBAC 配置页，管理员维护用户、角色、权限绑定和接口人绑定关系；接口人账号由部门接口人导入自动创建，用户管理不单独维护 `first_name`、`last_name` 等 Django 姓名类字段。

用户权限页建议拆成三个页签：

| 页签 | 主要能力 | 说明 |
| ---- | -------- | ---- |
| 用户管理 | 用户列表、新增/编辑/启停用户、绑定角色、绑定接口人 | 接口人用户由导入自动创建，用户名为工号；用户管理不展示/编辑 `first_name`、`last_name` 等姓名类字段，接口人姓名来自绑定 `Contact`；导入同步接口人角色时保留其它业务角色；二级/三级数据范围由绑定接口人和部门关系决定 |
| 角色管理 | 角色列表、新增/编辑/启停角色、复制角色 | 预置 HR、二级接口人、三级接口人、管理员；管理员可按需新增业务角色 |
| 权限配置 | 以树形权限点为角色勾选授权 | 权限点由后端预置，只允许勾选绑定，不允许前端随意新增未知权限码 |

权限树按模块组织：

| 模块 | 权限示例 |
| ---- | -------- |
| 简历库 | 查看、上传、撤销、导出、手动分配 |
| 主数据 | 岗位需求、院校清单、部门接口人的查看/导入/编辑/删除 |
| 分配工作流 | 查看工作流、查看尝试、单条下发、批量下发、一键全部下发、导出 |
| 接口人处理 | 二级转派、三级反馈、反馈查看 |
| 系统设置 | 配置项管理、用户权限管理 |

前端权限生效：
- 登录后调用 `/api/me/`，获得 `permissions`、`roles`、`contact`、`data_scope`。
- ProLayout 菜单按权限码过滤；页面按钮按权限码控制显示和禁用态。
- 无权限路由展示「无权限」页面；接口请求失败仍以后端 403 为准。
- 本地开发阶段使用系统账号密码登录并保存 Token；接口人账号用户名为工号，新账号默认密码为 `pass1234`；W3 认证接入后按工号识别用户并替换登录适配层，页面仍消费 `/api/me/`。

## 三、角色与可见性

权限体系采用 RBAC。前端不再写死角色能力，而是基于 `/api/me/` 返回的权限码、角色、接口人绑定和数据范围动态控制菜单、路由和按钮：

| 区域 | HR / 管理员 | 二级接口人 | 三级接口人 |
|------|-------------|------------|------------|
| 简历库（上传 / 撤销）/ 岗位 / 院校 / 部门接口人 | ✓ | ✗ | ✗ |
| 分配尝试 — 导出 / 反馈查看 | ✓ | ✓ | ✓ |
| 分配尝试 — 单条/批量/全部下发 / 分配策略切换 / 手动强制分配 | ✓ | ✗ | ✗ |
| 分配尝试 — 转派给三级接口人 | ✗ | ✓ | ✗ |
| 分配尝试 — 提交通过/未通过反馈 | ✗ | ✗ | ✓ |
| 系统设置 | ✓（管理员）| ✗ | ✗ |

> 二级/三级接口人登录后默认落到「分配尝试」，访问其它路径自动重定向回该页。
> **重要边界**：前端权限配置只负责体验和误操作拦截，不能替代后端鉴权。后端接口必须同步按权限码鉴权，并保证“二级只能看自己接收的尝试并只能转派本部门三级接口人”“三级只能看自己被转派的尝试”。

## 四、当前页面清单
1. 简历库：上传、撤销、筛选；按候选人一人一行展示当前志愿；详情查看全部投递、分配尝试和反馈结果。
2. 岗位需求、院校清单、部门接口人：主数据维护与导入。
3. 候选人工作流：查看流程状态、当前志愿、归档原因。
4. 分配尝试 / AI 决策：HR 单条/批量/全部下发、二级接口人转派、三级接口人反馈、导出、反馈查看；HR 查看 AI 决策、失败原因和建议归档记录，并可重试 AI。
5. 归档候选人：查看归档原因和志愿概览，从具体应聘ID发起手动强制分配，目标可选二级接口人或三级接口人。
6. 配置项：维护岗位类别字典、院校标签字典、院校标签准入规则、`ai_dispatch_threshold` / `ai_review_threshold` / AI 超时并发重试参数和系统参数；不维护南北省份字典，不维护大模型连接密钥。
7. 用户权限：维护用户、角色、权限绑定和接口人绑定关系，支撑 RBAC 前端配置。
