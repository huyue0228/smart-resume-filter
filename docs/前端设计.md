## 一、全局框架（ProLayout）

```
┌───────────────────────────────────────────────────────────┐
│ ▣ 智能简历筛选系统                    [当前用户 / 角色 ▾] │ 顶栏
├──────────────┬────────────────────────────────────────────┤
│ 数据管理 ▾    │                                            │
│   · 简历库    │            内容区                          │
│   · 岗位需求  │      (ProTable / Modal 导入)              │
│   · 院校清单  │                                            │
│   · 部门接口人│                                            │
│ 简历分配      │                                            │
│ 系统设置 ▾    │  ← 接口人身份时，左侧仅保留「简历分配」      │
│   · 配置项    │                                            │
│   · 用户权限  │                                            │
└──────────────┴────────────────────────────────────────────┘
```

> 当前结构：
> 1. **数据导入入口在各数据页内**：简历→简历库、岗位→岗位需求、院校→院校清单、接口人→部门接口人。
> 2. **处理由上传和策略切换触发**：上传简历后自动触发候选人处理主流程；分配页切换 Rule / AI 分配策略时，只重算「简历分类、分配与下发」环节。
> 3. **主要数据表格采用后端分页、表头筛选和列宽拖拽**：筛选参数进入接口查询，`page_size` 最大 500，导出全部按当前筛选条件执行。
> 4. **左侧菜单展开状态保持独立**：用户手动展开的一级菜单分组应保持展开；点击某个子页面只更新当前选中路由，不应自动收起其它已展开分组。
> 左侧菜单**按权限码和数据范围显示**：HR/管理员按授权菜单进入业务与设置页面；二级/三级接口人仅见与其数据范围匹配的「简历分配」。简历分配不再设置子页，点击后直接进入分配尝试操作台。**分配策略**位于分配工作流区域，分配页是其结果落点。

当前共享实现：

- `DataTableControls.jsx` 提供文本筛选、单选/多选筛选、筛选参数规范化和可拖拽列宽 Hook；筛选浮层统一提供确认、重置和取消操作；简历库、岗位、院校、接口人页面统一复用。
- `ResizableHeaderCell.jsx` 负责表头拖拽手柄和 pointer 事件；样式类 `.srf-column-resize-handle` 定义在全局 CSS。
- `ResumePreview.jsx` 负责 PDF/文件预览，PDF 通过鉴权 API 取得 Blob 后交给 PDF.js 渲染到 canvas，不依赖浏览器原生 PDF 内嵌能力；组件支持未选择、加载中、失败提示、分页、新窗口打开和“下载原文件”；可按 `resume` 直接预览，也可按 `attemptId` 走分配尝试数据范围预览。无权限或越权时不展示下载入口；PDF 渲染失败或非 PDF 文件时可下载原文件。
- 前端 API 封装位于 `src/api/services.js`：`previewResume`、`previewAllocationResume`、`exportCandidates`、`deleteCandidate` 分别对应预览、按筛选导出和候选人维护能力。

> **上传**：「上传简历」弹窗含两类文件 **① 简历信息列表 .xlsx / .xls / .csv + ② 简历包 .zip**。普通用户入口只提供安全的增量更新；主数据 replace 使用更新/停用语义，不得删除候选人流程、反馈或审计历史。测试环境彻底清空不放在普通上传弹窗中。
> **上传即处理**：上传成功后自动按当前分配策略运行 `Step1 查重与志愿排序 → Step2 简历分类、分配与下发`，前端按环节驱动进度条。院校分类 Step3 和需求数据准备核对 Step4 是前置数据准备，可在对应主数据页提前维护或独立运行；显式“全流程”操作才按 `Step3 → Step4 → Step1 → Step2` 执行。「处理简历」按钮只跑带筛选范围的 Step2，不重跑查重排序、全量院校分类和需求核对；后端会在锁定当前筛选范围后，为范围内缺失院校标签的候选人补齐标签，不覆盖已有标签。
> **增量 + 冲突处理**：按 `normalized_name + normalized_phone` 归并候选人，按 `应聘ID` 幂等更新投递；低风险重复更新当前主记录，但不删除已反馈流程、分配尝试和历史快照；高风险重复进入导入错误清单。手机号缺失的候选人直接舍弃，不入库、不进入分配，并在导入结果中提示。
> **候选人聚合展示**：主列表以 `Candidate` 为行粒度，一名候选人只显示一行；主列表不展示候选人手机号，手机号只在详情抽屉/详情页展示；主列表和详情都展示 `Candidate.highest_major` 最高学历专业；所有投递岗位、应聘ID、志愿顺序、分配尝试、匹配/手动理由和反馈记录进入详情抽屉/详情页。
> **当前志愿展示**：主列表仅展示当前有效志愿。初始只展示第一志愿；第一志愿反馈未通过后，系统生成并展示下一志愿；通过后固定展示通过志愿；归档后展示最后处理志愿和归档原因；当前志愿匹配岗位和二级部门但缺可用二级接口人时，固定展示当前志愿和阻塞原因。
> **系统简历状态**：简历库展示后端推导的统一状态，不覆盖导入文件中的原始“应聘状态”。状态选项为：待处理、已分类、已分配、待筛选、筛选通过、筛选不通过；存在历史未通过和下一志愿活动尝试时，按 `筛选通过 > 待筛选 > 已分配 > 筛选不通过 > 已分类 > 待处理` 展示，但只读取当前 workflow、当前通过指针和未取消活动尝试，历史 passed/rejected/cancelled 只在详情中展示，不覆盖重开后的当前状态。
> **筛选、处理与导出**：主列表筛选在表头内完成，支持姓名/全拼/拼音首字母、最高学历专业、当前志愿、当前应聘ID、招聘主体、当前岗位、岗位部门、岗位类别、院校标签、系统简历状态、流程状态、原因类型等字段；系统简历状态和流程状态都使用表头勾选多选筛选。工具栏提供「处理简历」按钮，HR/管理员点击后在弹窗中勾选一个或多个目标系统简历状态，按钮按弹窗状态选择和当前表格其它筛选条件触发 Step2 重新分配，未选择状态时前端提示先选择状态。该入口可按筛选范围重开已通过、已归档或已不通过候选人流程，前端需在弹窗文案中提示会保留历史尝试/反馈并生成新的自动尝试；「导出当前筛选」按后端筛选结果导出，单个可用文件且没有缺失清单时直接下载原文件，多个文件或存在缺失清单时下载 zip；前端读取导出响应头 `X-Export-Count` / `X-Export-Missing` 展示命中和缺失数量。
> **简历预览与删除**：详情抽屉默认选中当前投递中有文件的简历；当前投递无文件时，自动回退到同候选人第一条有文件的投递，不改变当前志愿展示口径。候选人多条投递间可手动切换预览，未关联简历文件的投递预览入口置灰并提示原因；前端通过鉴权 API 获取 PDF Blob 后用 PDF.js 渲染到 canvas，并读取预览响应头 `X-Resume-Filename` 展示原始文件名。无权限或越权时不展示预览和下载入口；PDF 渲染失败或非 PDF 文件时可下载原文件。候选人存在分配尝试、反馈、AI 决策或转派历史时不显示可执行删除，或保持禁用并解释原因；后端返回 409 时展示原始错误说明。
> **单级撤销**：后端先解析本次上传影响的业务键，只为该候选人/投递范围保存覆盖 Candidate / Resume / ResumeProfile / CandidateWorkflow / AgentDispatchDecision / AssignmentAttempt / AssignmentHandoff 的快照；「撤销上次上传」只恢复该范围，不回滚无关候选人的并发操作。对应 ProcessingRun 保留且展示“已撤销”，便于审计。仅保留最近一次（单级）。

```
│ ...    │...   │...   │... │...│...│...│...│...    │编辑 删除

│ 姓名 │ 工号 │ 所属部门 │ 部门层级 │ 接口人层级 │ 可转派
```
> 三页各自只导入对应的一张表格文件（.xlsx / .xls / .csv）；后端复用同一 `/api/import/`（按字段区分），无需分别建接口。
> 岗位、院校、部门接口人列表均使用表头筛选和列宽拖拽；筛选条件进入后端查询并与分页共同生效。岗位支持主体、发布名称、岗位族、部门、地点、学历、HC、是否发布等筛选，并提供编辑和删除操作；删除岗位采用停用/失效语义，历史投递和分配尝试仍可追溯。院校清单前端只展示学校和院校标签，不展示所在地/所在省份；省份字段可作为导入和排序规则后台数据保留。接口人支持姓名、工号、部门、层级、是否可转派、是否启用筛选；不展示或筛选招聘主体归属/主体来源。
> 部门接口人 replace/清空重导时，本次文件中不存在的旧接口人及其绑定账号会同步停用；列表默认只展示启用接口人，可通过状态筛选查看停用接口人。单条“删除”操作采用清理语义：删除接口人并同步删除绑定用户，历史分配记录不删除，只通过快照字段展示原接口人信息。
> **字典化口径**：岗位类别来自 `JobCategory` 字典，院校标签来自 `SchoolTag` 字典，专业大类词表来自 `MajorCategory` + `MajorAlias`；字典项保留 `code + name` 或规范化名称，前端展示业务名称，导入/匹配优先使用 `code` 或规范化名称。
> **院校标签准入规则**：配置项中维护 `SchoolTagRule`，规则允许标签通过 `SchoolTagRuleTag` 关联到 `SchoolTag`，并区分第一学历/最高学历两个作用域。
> **招聘主体**：岗位和投递引用 `RecruitingEntity.code`，前端直接展示 GW / YLS 等主体编码；部门和部门接口人不建立“属于招聘主体”的关系。
> **省份口径**：`School` 只保存所在省份 `province`；系统不维护南北省份字典或 `ProvinceRegion`，南北归属仅在志愿排序规则运行时计算，不落库、不作为配置页维护项。

### 3) 候选人处理主流程（随上传/换策略自动触发）
处理由两个动作触发，均以**进度条**呈现：
- **上传简历**（简历库）→ 自动跑候选人处理主流程；
- **切换 Rule / AI 分配策略**（简历分配页）→ 只重算「简历分类、分配与下发」环节。

> 正式 AI Agent 未落地前，生产环境不展示 AI 模式，或点击后明确提示“尚未实现”且不触发处理；不得把 Rule 结果、固定置信度或 demo 画像展示为 AI 结论。

```
前置数据准备：
  院校分类、需求录入、部门接口人维护

候选人处理主流程：
  Step1 查重与志愿排序 → Step2 简历分类、分配与下发
```
> 院校分类和需求录入提前完成，保证分配时院校标签、岗位需求、专业要求和接口人已就绪。
> 前端逐步调用 `/api/pipeline/run/` 推进进度条；后端同步/异步执行方式和 `ProcessingRun` 记录口径见 `docs/后端设计.md`。

> **分配策略**：页头提供一个分段器「Rule / AI」。切换前先弹确认；确认后只重算「简历分类、分配与下发」环节。选择存于前端（localStorage），上传简历时也读取当前选择。
> **Rule 策略**：按志愿顺序、院校标签准入规则、招聘主体一致性、岗位需求映射、岗位需求专业、岗位二级部门和二级接口人生成待下发尝试；岗位未配置需求专业，或岗位需求专业为“专业不限 / 不限 / 不限专业”等通配表达时，不阻断自动分配。岗位配置非通配需求专业时，后端先用专业大类词表判断候选人最高学历专业与岗位需求专业是否同属大类；若大类无交集，或候选人/岗位任一侧未映射到启用大类，则再用专业名双向包含兜底。当前志愿匹配岗位和二级部门但缺可用二级接口人时，前端不展示下一志愿，而是在简历库显示阻塞原因。多岗位命中时后端按同主体、精确匹配、对外发布名称、职位名称和包含匹配的固定顺序选择岗位，并在尝试详情展示岗位、专业大类/专业名、部门和接口人等匹配理由。
> **AI 策略（目标设计）**：Agent 只处理候选人的当前有效志愿，硬规则先行，不跨志愿跳转。Agent 读取 PDF 简历解析出的 `raw_text` / `ResumeProfile`，结合当前志愿、岗位需求专业与部门信息生成建议。达到 `ai_dispatch_threshold` 形成 `pending_dispatch`；达到 `ai_review_threshold` 但未达到自动下发条件时形成 `pending_review`；建议归档、低于复核阈值、简历缺失、解析失败或最终失败时只展示 AI 决策，不生成分配尝试，候选人流程显示为“已归档 / AI 无有效建议”。AI 运行期间展示已处理、待下发、待复核、失败和建议归档数量；`partial_failed` 必须显示警告，不得提示完全成功。
> **分配尝试**：展示 `AssignmentAttempt`，支持状态筛选、导出、下发、转派、反馈、查看详情和简历预览。HR/管理员视图可见待复核、待下发、已下发等全流程状态；二级接口人视图是个人处理界面，只展示已由 HR 下发给自己的尝试，不展示 `pending_dispatch` / `pending_review` 等 HR 待处理状态，也不提供“二级接口人”筛选项。接口：`/api/workflow-attempts/`。
> **AI 复核操作**：HR 可在 `pending_review` 尝试详情中确认下发、取消、转人工处理或重试 AI；分别调用 `confirm-review`、`cancel-review`、`transfer-to-manual` 和 AgentDecision `retry` 接口。取消后若没有其它活动尝试，简历库显示 `agent_no_recommendation` 归档；转人工时必须从该尝试的具体投递进入手动分配，不允许隐式换志愿。
> **待下发取消**：HR 可取消 `pending_dispatch` 尝试，调用 `POST /api/workflow-attempts/{id}/cancel/`；取消后刷新候选人当前状态和可执行操作。
> **AI 失败边界**：AI 超时、调用失败、PDF 解析失败、输出不合法、推荐对象不存在或被硬规则拦截时，不自动回退 Rule；前端提示失败原因，由 HR 明确选择重试 AI、切换 Rule 或手动强制分配。
> **AI 决策详情**：HR 可在尝试详情查看 AI 推荐动作、推荐岗位/岗位类别/二级部门/二级接口人、总置信度、分项评分、推荐理由、简历证据和风险点。系统不保存完整 LLM 原始响应；接口人只看到已下发给自己的尝试和必要简历信息。
> **AI 决策列表**：展示所有 AI 决策，包括未生成 `AssignmentAttempt` 的失败、低置信度和建议归档记录；HR 可在该列表或简历库归档详情中重试 AI、切换 Rule 或发起手动强制分配。重试接口：`POST /api/agent-decisions/{id}/retry/`。
> **详情与预览**：分配尝试详情抽屉展示候选人、应聘ID、岗位、二级/三级接口人、状态、反馈备注等信息，并通过 `/api/workflow-attempts/{id}/resume-preview/` 在当前用户数据范围内获取 PDF Blob，再用 PDF.js 渲染到 canvas。接口人账号只能预览自己可见分配尝试的简历；越权尝试由后端返回 404/403 类错误，前端展示为不可预览且不提供下载入口。PDF 渲染失败或非 PDF 文件时，保留下载原文件入口。
> **导出**：导出候选人**简历文件**（`/api/workflow-attempts/export/`）；支持单条、勾选批量、按筛选「导出全部」。单条且命中一个可用文件、没有缺失清单时直接下载原文件；批量、多文件或存在缺失清单时下载 zip，缺失候选人写入压缩包内「缺失简历文件清单.txt」。前端读取 `X-Export-Count` / `X-Export-Missing` 展示导出统计。
> **HR 下发操作**：HR 可单条下发，也可勾选多条后「下发选中」，或按当前筛选条件「一键全部下发」。批量下发只处理 `pending_dispatch`，其他状态自动跳过并提示成功/跳过数量。接口：`POST /api/workflow-attempts/bulk-dispatch/`。
> **下发、转派与反馈**：HR 将待下发尝试下发至二级部门接口人；二级接口人在本二级部门范围内选择三级部门接口人并转派；三级接口人对已转派尝试提交通过/未通过 + 可选备注，提交后锁定。
> **转派操作**：二级接口人的分配尝试列表展示「转派」按钮，弹窗只列出当前二级部门下启用的三级接口人；转派后状态变为「已转派三级」，并记录转派历史。
> **手动强制分配**：HR 从具体应聘ID打开弹窗，先选择目标类型（二级接口人 / 三级接口人），再选择对应接口人。选择二级接口人时走普通下发与二级转派链路；直接选择三级接口人时，前端展示其父级二级部门：若只有一个有效二级接口人则自动补齐，若有多个则要求 HR 明确选择，确认后进入「已转派三级 / 待反馈」并展示两段转派历史。没有有效父级二级接口人时阻止提交并提示改选二级接口人。已通过候选人不可通过该入口再次强制分配；如需重开已通过候选人，使用简历库「处理简历」入口。
> **归档候选人**：归档原因、志愿概览和从具体应聘ID发起手动强制分配统一合并到简历库；不再作为 HR 独立菜单入口。
> **角色差异**：二级接口人仅看到已下发给自己的尝试，可导出、查看反馈和转派给本部门三级接口人；三级接口人仅看到转派给自己的尝试，可导出并提交反馈；接口人均无 HR 下发、手动分配、二级接口人筛选和模式开关。

AI 决策详情建议布局：

| 区域 | 展示内容 |
| ---- | -------- |
| 推荐结论 | 推荐动作、推荐岗位、岗位类别、二级部门、二级接口人 |
| 置信度 | 总分 + 专业匹配、技能匹配、项目/实习证据、岗位需求覆盖、部门确定性、简历质量分项 |
| 业务理由 | 一句话摘要、推荐理由 |
| 简历证据 | 项目、实习、技能、专业、教育等证据摘要 |
| 风险点 | 解析失败、文本过短、项目不足、专业不明确、推荐对象不存在等提示 |
| 操作 | 确认下发、取消、转人工处理、重试 AI |

### 6) 业务配置与系统设置（设计 · M4/M6）
- **配置项**：岗位类别字典、院校标签字典、院校标签准入规则、专业大类映射词表、`ai_dispatch_threshold`（默认 0.75）、`ai_review_threshold`（默认 0.5）、AI 超时、AI 并发、AI 重试次数、AI 重试退避；不维护南北省份字典。W3 认证属于待实现的安全适配，不作为通用业务配置项。
- **AI 连接配置边界**：前端配置页只维护阈值、超时、并发、重试次数和退避等非敏感运行参数；大模型供应商、模型名、API Key 环境变量名、Base URL 环境变量名、提示词版本和决策版本由后端配置文件读取环境变量管理。前端不展示、不编辑、不接收真实 API Key。
- **准入规则配置**：规则表单从 `SchoolTag` 字典勾选标签，保存为 `SchoolTagRule` + `SchoolTagRuleTag`；第一学历允许标签和最高学历允许标签分开配置，但候选人必须在同一条启用规则内同时命中第一学历和最高学历标签才算通过；多条启用规则之间 OR，没有启用规则时视为不做院校准入过滤。
- **专业大类词表配置**：配置项新增「专业大类词表」页签。页面展示专业大类列表和当前大类下的专业别名/关键词，支持新增、编辑、停用、删除；字段包括大类编码、大类名称、大类说明、排序、专业别名、匹配方式（精确 / 包含）、来源、备注和启用状态。内置词表可编辑和停用；专业大类存在任何别名时不允许直接删除，确需删除需先删除或迁移别名，后端返回明确错误时前端以消息提示。
- **用户权限**：RBAC 配置页，管理员维护用户、角色、权限绑定和接口人绑定关系；接口人账号由部门接口人导入自动创建，用户管理不单独维护 `first_name`、`last_name` 等 Django 姓名类字段，并支持删除用户。

> 权限分区：岗位类别、院校标签、院校准入规则、专业大类词表和 AI 非敏感运行参数属于业务配置，可分别授权 HR/管理员；用户、角色、权限、认证和安全开关属于系统设置，仅管理员可见。前端按具体权限码控制页签，不以“是否管理员”硬编码整个配置页。
> 配置页通过 `GET /api/configs/` 获取白名单项，通过 `PATCH /api/configs/{key}/` 更新；未知配置、类型错误或越权由后端拒绝。页面不提供任意新增/删除配置键，也不展示模型连接信息或真实密钥。

用户权限页建议拆成三个页签：

| 页签 | 主要能力 | 说明 |
| ---- | -------- | ---- |
| 用户管理 | 用户列表、新增/编辑/启停/删除用户、绑定角色、绑定接口人 | 接口人用户由导入自动创建，用户名为工号；用户管理不展示/编辑 `first_name`、`last_name` 等姓名类字段，接口人姓名来自绑定 `Contact`；导入同步接口人角色时保留其它业务角色；删除用户采用账号清理语义，删除账号、Token 和角色绑定，若用户绑定接口人则同步删除接口人；历史审计和分配记录不删除，只保留快照展示；二级/三级数据范围由绑定接口人和部门关系决定 |
| 角色管理 | 角色列表、新增、编辑角色 | 预置 HR、二级接口人、三级接口人、管理员；管理员可按需新增业务角色；Django Group 暂不提供独立启停状态 |
| 权限配置 | 以树形权限点为角色勾选授权 | 权限点由后端预置，只允许勾选绑定，不允许前端随意新增未知权限码 |

前端权限生效：
- 登录后调用 `/api/me/`，获得 `permissions`、`roles`、`contact`、`data_scope`。
- ProLayout 菜单按权限码过滤；页面按钮按权限码控制显示和禁用态。菜单的展开分组由前端显式维护，路由跳转和子页选择只影响选中态，不清空其它已展开分组。
- 无权限路由展示「无权限」页面；接口请求失败仍以后端 403 为准。
- 本地开发阶段使用系统账号密码登录并保存 Token；接口人账号用户名为工号，新账号默认密码为 `pass1234`；W3 认证接入后按工号识别用户并替换登录适配层，页面仍消费 `/api/me/`。

## 三、角色与可见性

权限体系采用 RBAC。前端不再写死角色能力，而是基于 `/api/me/` 返回的权限码、角色、接口人绑定和数据范围动态控制菜单、路由和按钮：

| 区域 | HR / 管理员 | 二级接口人 | 三级接口人 |
|------|-------------|------------|------------|
| 简历库（上传 / 撤销）/ 岗位 / 院校 / 部门接口人 | ✓ | ✗ | ✗ |
| 分配尝试 — 导出 / 反馈查看 | ✓ | ✓ | ✓ |
| 分配尝试 — 单条/批量/全部下发 / 分配策略切换 / 手动强制分配 | ✓ | ✗ | ✗ |
| 分配尝试 — 转派给三级接口人 | ✗ | ✓ | ✗ |
| 分配尝试 — 提交通过/未通过反馈 | ✗ | ✗ | ✓ |
| 业务规则配置 | 按权限码授权 HR / 管理员 | ✗ | ✗ |
| 用户权限与安全设置 | ✓（管理员）| ✗ | ✗ |

> 二级/三级接口人登录后默认落到「简历分配」，访问其它路径自动重定向回分配尝试操作台。
> **重要边界**：前端权限配置只负责体验和误操作拦截，不能替代后端鉴权。后端接口必须同步按权限码鉴权，并保证“二级只能看自己接收且已下发的尝试并只能转派本部门三级接口人”“三级只能看自己被转派的尝试”。
