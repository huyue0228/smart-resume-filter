> 脚手架：**Vite + React 18 + Ant Design + @ant-design/pro-components**（ProLayout / ProTable）。语言 JavaScript（.jsx）。
> 后端：Django + DRF。本稿含**线框设计**与**当前实现状态（v1）**两层信息。

## 一、全局框架（ProLayout）

```
┌───────────────────────────────────────────────────────────┐
│ ▣ 智能简历筛选系统                    [演示身份: HR ▾] │ 顶栏
├──────────────┬────────────────────────────────────────────┤
│ 数据管理 ▾    │                                            │
│   · 简历库    │            内容区                          │
│   · 岗位需求  │      (ProTable / Modal 导入)              │
│   · 院校清单  │                                            │
│   · 部门接口人│                                            │
│ 处理流水线 ▾  │                                            │
│   · 流水线运行│                                            │
│ 简历分配 ▾    │                                            │
│   · 分配结果  │                                            │
│ 系统设置 ▾    │  ← 接口人身份时，左侧仅保留「简历分配」      │
│   · 配置项    │                                            │
│   · 用户权限  │                                            │
└──────────────┴────────────────────────────────────────────┘
```

> 设计调整：**不再设独立「数据导入」菜单**——导入是各类数据的一个动作，入口下沉到对应数据页（简历→简历库、岗位→岗位需求、院校→院校清单、接口人→部门接口人）。
> 左侧菜单**按角色显示**：HR/管理员见全部；接口人仅见「简历分配 / 分配结果」。规则/AI 开关不放全局，放在用到 AI 的步骤上（Step2/Step5）。

## 二、关键页面

### 1) 简历库（ProTable + 导入）
```
简历库                          [↥ 导入简历] [+ 新增] [导出]
┌ 筛选: 导入时间[范围] 状态[▾] 🔍姓名/手机
├──────────────────────────────────────────────────────────
│ 姓名 │手机│主体│投递岗位│志愿│岗位类别│院校标签│状态  │操作
│ 张三 │138│GW │后端    │ 1 │技术类  │平台A   │待处理│查看 编辑 删
│ 张三 │138│YLS│产品    │ 2 │产品类  │平台A   │待处理│ …  （同一人多投）
└ 分页 / 共 N 条
```
> 「导入简历」弹窗内含两类文件：**① 简历信息列表 .xlsx + ② 简历包 .zip**，加导入模式（增量/清空重导）。同一人多条投递（Candidate → 多 Resume）通过 identity_hash 归并。

### 2) 岗位需求 / 院校清单 / 部门接口人（结构同构）
```
岗位需求                                       [↥ 导入岗位]
│ 对外名称│职位名称│岗位类别│岗位族│部门│工作地│学历│HC│对外发布│

院校清单                                       [↥ 导入院校]
│ 学校 │ 平台标签 │ 所在地(南/北) │

部门接口人                                     [↥ 导入接口人]
│ 姓名 │ 工号 │ 所属部门 │ 招聘主体 │   ← 接口人本人信息，简历下发接收人
```
> 三页各自只导入对应的一张 xlsx；后端复用同一 `/api/import/`（按字段区分），无需分别建接口。

### 3) 流水线运行
```
处理流水线
┌ 处理范围: 导入时间[范围] 状态[待处理 ▾]    （作用于数据池的筛选条件）
├──────────────────────────────────────────────────────────
│ Step1 查重与志愿排序   规则        [运行]  ● 完成        │
│ Step2 岗位分类        (·)规则 ( )AI [运行]  ◐ 运行中      │
│ Step3 院校分类        规则        [运行]  ○ 未运行       │
│ Step4 需求录入        规则        [运行]  ○              │
│ Step5 简历分配        (·)规则 ( )AI [运行]  ○              │
│                                   [一键全流程]            │
├──────────────────────────────────────────────────────────
│ 运行记录: step / 模式 / 状态 / message / 时间             │
```
> 一键全流程实际执行顺序为 **Step1 → Step3 → Step2 → Step4 → Step5**（院校分类提前，保证分配时目标院校已就绪）。demo 同步执行（Celery eager），运行记录来自 ProcessingRun。

### 4) 各步结果 / 规则 vs AI 对比（设计，未实现 · M5）
```
Step2 岗位分类结果      [ 规则 | AI | 对比 ]            [导出]
│ 姓名│投递岗位│规则类别│AI类别│AI 理由      │一致│操作    │
│ 李四│数据    │未匹配  │技术类│"数据≈技术…"│ ✗ │采纳 AI  │
```

### 5) 简历分配 / 导出 / 下发
```
简历分配（Step5）              [↧ 导出选中(n)] [↧ 导出全部]
┌ 筛选: 状态[▾] 候选人 投递岗位
├──────────────────────────────────────────────────────────
│☑│候选人│投递岗位│分配部门│接口人│分配理由│状态  │操作       │
│☑│张三  │后端    │后端组  │王工  │志愿优先│待下发│导出 下发   │
└ 勾选行 → 批量导出；导出全部按当前筛选打包
```
> **导出**：把候选人**简历文件**打包成 zip 下载（`/api/allocations/export/`）；支持单条（行内「导出」）、勾选批量、按筛选「导出全部」。无文件的候选人写入压缩包内「缺失简历文件清单.txt」。
> **下发**：状态 待下发 → 已下发（demo 仅改状态/记时间，真实 WeLink 推送见 M7）。
> **角色差异**：**接口人身份下，操作列仅「导出」，无「下发」**；其只能看到「分配结果」一页。

### 6) 系统设置（占位 · M4/M6）
- **配置项**：分配倍数、南北省份字典（省份→南/北）、W3 认证开关。
- **用户权限**：用户列表 + 角色（HR / 接口人 / 管理员），RBAC。

## 三、角色与可见性

v1 用**前端演示角色**实现（`RoleContext` + localStorage，顶部「演示身份」下拉切换，无真实登录）：

| 区域 | HR / 管理员 | 接口人 |
|------|------------|--------|
| 简历库 / 岗位 / 院校 / 部门接口人 | ✓ | ✗ |
| 处理流水线 | ✓ | ✗ |
| 分配结果 — 导出 | ✓ | ✓ |
| 分配结果 — 下发 | ✓ | ✗ |
| 系统设置 | ✓（管理员）| ✗ |

> 接口人登录后默认落到「分配结果」，访问其它路径自动重定向回该页。
> **重要边界**：v1 的隔离只是**前端遮挡**，后端仍 AllowAny；真正的接口级隔离（含"接口人只能看/导自己名下"）需 M6 接入 RBAC + 登录后在后端按身份过滤。

## 四、与设计稿的主要差异（演进记录）
1. 取消独立「数据导入」页，导入入口下沉各数据页。
2. 接口人视角由「我的待领取（先到先得领取）」简化为**「分配结果（仅导出）」**；领取/先到先得留待 M7。
3. 分配页新增**简历文件导出**（行内/批量/全部）。
4. 角色隔离先做前端演示版，真实鉴权延后 M6。
