# 智能简历筛选系统 — 设计文档

- 日期：2026-06-23
- 状态：待评审

## 1. 背景与目标

校招场景下，HR 需要对大批量学生投递简历做去重、分类、分配。当前流程依赖人工处理 Excel，效率低、易出错。

本系统将固定的 5 步处理流程产品化：以「简历批次」为单位，依次执行 **查重+志愿排序 → 岗位分类 → 院校分类 → 需求录入 → 简历分配**，每步可独立运行、可重跑、产出可预览可导出，人工审核后进入下一步；最终把分配结果下发给二层部门接口人。

**核心约束（已与需求方确认）：**

- 输入：结构化简历表格（已提取好字段）+ 原始简历文件，二者通过**简历ID**一一对应（简历ID 同时体现在表格行和原始文件名上）。
- 规模：单批次 1–10 万条，需异步任务 + 进度反馈。
- 智能策略：规则引擎与 LLM **可配置开关**，用户每步自选。
- 部署：内网/私有，Docker Compose。简历含隐私，数据默认不出内网。
- LLM：通过 **OpenAI 兼容协议** 接入，base_url/key 可配置（由部署方填入内部网关或获授权的外部 API），系统不绑定具体供应商。
- 角色：多角色登录（HR 管理员、部门接口人），RBAC。

## 2. 关键业务定义

- **主体**：GW、YLS 是两个招聘主体。每位同学在单一主体内最多投递 2 个岗位；若两个主体各投 2 个，共最多 4 个岗位。
- **同一同学的唯一识别**：`姓名 + 手机号`。
- **南北方判定**：走**可配置省份清单**（省份 → 南/北 映射，默认按秦岭淮河，管理员后台可调）。先用户籍地址判定；户籍缺失时用学校所在地。
- **院校标签**：数据驱动。目标院校清单表含「学校名称 + 标签名」，按学校名称直接查表打标签；不预设 985/211 固定体系。

## 3. 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | Python + FastAPI | Excel 处理（pandas/openpyxl）、LLM 生态、异步 + Pydantic 类型校验 |
| 异步任务 | Celery + Redis | 1–10 万量级需异步 + 进度反馈 |
| 数据库 | PostgreSQL | JSONB 存灵活简历字段，复杂筛选/排序强 |
| ORM/迁移 | SQLAlchemy + Alembic | 标准组合 |
| 前端 | React + Ant Design Pro | 中后台标杆，内置 RBAC、高级表格、批量操作、表单 |
| 文件存储 | MinIO（S3 兼容，自托管） | 原始简历留底，内网自托管 |
| LLM 接入 | OpenAI 兼容客户端 | base_url/key/model 可配置，每步骤开关 |
| 鉴权 | JWT + RBAC | 多角色 |
| 部署 | Docker Compose | 内网私有，一键起全栈 |

## 4. 整体架构与工作流

```
HR 上传(简历表格 + 原始文件) ──► 创建批次
        │
        ├─ 维护映射/配置表(岗位类别映射、目标院校清单、省份南北、接口人清单) [可复用]
        ▼
[1 查重+志愿排序] ─► [2 岗位分类] ─► [3 院校分类] ─► [4 需求录入] ─► [5 简历分配]
        每步: 异步任务 + 进度条 → 结果预览 → 人工微调 → 导出清单
        ▼
分配结果 ──► 下发二层部门接口人(系统内工作台查看 + 导出)
        ▼
接口人登录 ─► 查看分配给自己的简历 ─► 下载原始文件 ─► 标记处理状态
```

每步骤是独立服务模块，统一接口：`输入(批次状态 + 配置/映射) → 异步执行 → 输出(更新记录 + 可下载清单)`，幂等可重跑，规则/LLM 由该步配置项切换。

## 5. 数据模型

- **User / Role**：用户、角色（HR 管理员、部门接口人），RBAC 权限。
- **Batch（批次）**：一次处理运行；记录各步骤执行状态、参数快照、产出版本。
- **Resume（简历）**：
  - 原始字段：简历ID、姓名、手机号、户籍地址、学校、学校所在地、投递主体(GW/YLS)、投递岗位、投递时间、专业、第一学历、最高学历、原始文件引用。
  - 流水线产出字段：学生唯一键(姓名+手机号哈希)、志愿排序、岗位类别标签、第一学历院校标签、最高学历院校标签、状态(待处理/已分配/已处理…)、分配信息。
  - 灵活附加字段统一存 JSONB。
- **映射/配置表（均支持 Excel 导入、版本化）**：
  - 岗位类别映射表（投递岗位 → 岗位类别）
  - 目标院校清单（学校名称 → 标签名）
  - 省份南北映射（省份 → 南/北）
  - 接口人清单（部门 → 二层部门接口人）
- **Demand（需求）**：部门、岗位、HC、目标院校、专业要求等（步骤4 结构化产出）。
- **Assignment（分配记录）**：简历 → 部门 / 接口人，含分配理由与时间。
- **AuditLog**：关键操作审计。

## 6. 五步流水线详细逻辑

### 步骤1 查重 + 志愿排序
- 输入：简历库 + 省份南北映射。
- 逻辑：
  1. 按 `姓名+手机号` 聚合识别同一同学。
  2. 单主体内：按投递时间标记第一志愿、第二志愿（最多 2 个）。
  3. 跨主体：按规则排第一~第四志愿。户籍为南方 → YLS 优先；户籍为北方 → GW 优先；户籍缺失 → 用学校所在地按同规则判定。
- 输出：按志愿排序整理后的学生投递简历清单。

### 步骤2 岗位分类
- 输入：简历库 + 岗位类别映射表。
- 逻辑：按投递岗位映射到岗位类别打标签；映射缺失时，若开启 LLM 则做模糊匹配并给出建议（标记为待确认）。
- 输出：打完岗位类别标签的清单。

### 步骤3 院校分类
- 输入：简历库 + 目标院校清单。
- 逻辑：
  1. 对第一学历、最高学历分别按学校名称**精确/规则匹配**院校清单打标签。
  2. **校名模糊识别（LLM，重点能力）**：学生常写简称/别名（如"北邮""华科""中传"），规则匹配不中时，调用 LLM 将其归一化到院校清单中的标准校名，再打标签。匹配结果带置信度，低置信度标记为"待人工确认"。
  3. LLM 关闭或调用失败时，回退为仅规则匹配，未命中项标记为"未识别院校"，不阻断流程。
  - 优化：对模糊匹配结果做缓存（同一简称只识别一次），降低 LLM 调用量与成本。
- 输出：每条简历新增「第一学历院校标签」「最高学历院校标签」两个字段。

### 步骤4 需求录入
- 输入：校招需求汇总表。
- 逻辑：解析为结构化需求表（部门、岗位、HC、目标院校、专业要求）；字段不规整时可选 LLM 辅助结构化。
- 输出：结构化需求表。

### 步骤5 简历分配
- 输入：简历库 + 需求表 + 接口人清单。
- 筛选：状态=待处理 ∧ 第一志愿 ∧ 符合目标院校。
- 分配：按部门分配，数量 = 最大 HC × 5（可配置）；原则：志愿优先 → 专业匹配 → 若相同/相似岗位对外只发布一个，则在同类型简历中按需求数量同比例分配。专业匹配可选 LLM 语义判断。
- 执行：下发至二层部门接口人（系统内工作台 + 导出）。

## 7. 错误处理与可靠性

- 上传校验：表格表头/必填字段校验；简历ID 与原始文件一一对应性校验，缺失/多余文件给出清单。
- 异步任务：每步进度反馈、失败可重试、错误行汇总（不中断整批）。
- 幂等重跑：每步可基于上一步产出重新执行，覆盖本步产出版本。
- LLM 容错：超时/失败回退到规则或标记"待人工确认"，不阻断流程。
- 数据隔离：批次间数据隔离；接口人只能看到分配给自己的简历。

## 8. 安全与权限

- JWT 登录，RBAC：HR 管理员（全流程 + 配置）、部门接口人（仅本人分配结果）。
- 原始简历文件经 MinIO 预签名/受控下载，记录审计。
- 全栈内网部署，LLM 调用走可配置网关，默认不出内网。

## 9. 交付输出件

1. 设计文档（本 spec）+ 实施计划。
2. 后端服务：API、5 个流水线模块、数据模型、Celery 异步任务、LLM 适配层、RBAC 鉴权。
3. 前端：批次管理、5 步操作页、映射表管理、分配看板、接口人工作台、用户/角色管理。
4. 数据库 schema + Alembic 迁移。
5. Excel 模板：简历库、岗位类别映射表、目标院校清单、需求汇总表、省份南北映射、接口人清单。
6. Docker Compose 一键部署（postgres + redis + minio + backend + worker + frontend/nginx）。
7. OpenAPI 接口文档 + 部署文档 + 操作手册。

## 10. 测试策略

- 单元测试：5 步流水线的规则逻辑（志愿排序、南北判定、同比例分配等）用构造数据覆盖边界。
- 集成测试：上传 → 各步骤 → 分配的端到端流程。
- LLM 模块：mock OpenAI 兼容接口，测试开关与回退路径。
- 鉴权测试：角色越权访问拦截。

## 11. 暂不做（YAGNI）

- 原始简历的 OCR/解析（表格已含提取字段）。
- 简历评分/AI 面试等超出 5 步范围的能力。
- 多租户 SaaS（内网单租户即可）。
- K8s 编排（Compose 满足）。
