需求：开发智能简历筛选系统
形式：网页，涉及到后端和前端开发，在简历筛选中加入OpenAI的LLM接口，使简历筛选存在规则和AI两种模式，通过开关切换
时间：七月底交付一个可用版本

本需求存在一下输入件：
1. 简历信息列表.xlsx（表头：招聘主体，所属机构，姓名，应聘ID，手机号，性别，对外职位名称，学历，第一学历毕业院校，最高学历毕业院校，最高学历专业，应聘状态，户口所在地，应聘日期）
2. 校招岗位分类及专业要求.xlsx（表头：主体，一层部门，二层部门，岗位类别，对外发布名称，是否对外发布，职位名称，岗位族，工作地点，学历，需求专业，需求数量）
3. 院校分类.xlsx（表头：学校，平台）
4. 部门接口人信息.xlsx(序号，一层部门，二层部门，姓名，工号)
5. 简历包（命名格式：姓名（应聘ID）。例如：张三（12345））

以下是hr部门对简历筛选系统的设想：
#  第一步：简历查重
1. 输入：简历库 + 地域分布
2. 查重逻辑：
	1. 每个同学单一主体最多投递两个岗位，根据投递时间标记第一志愿和第二志愿；若同学两个主体分别投递两个岗位，则四个岗位按照规则标记第一至第四志愿。具体根据户籍地址和学校所在地进行排序。具体规则如下：
		1. 户籍为北方：优先分配给GW
		2. 户籍为南方：优先分配给YLS
		3. 若户籍缺失，则按照学校所在地按相同规则分配
3. 输出：根据志愿排序整理后的学生投递简历清单

# 第二步：简历分类
1. 输入：简历库+岗位类别映射表
2. 分类逻辑：
	1. 根据投递岗位，参照岗位类别映射表，进行标签分类
	2. 优先根据投递岗位映射到岗位类型
3. 输出：根据岗位类别打完标签后的学生投递简历清单

# 第三步：院校分类
1. 输入：简历库+院校清单
2. 分类逻辑：按照简历中的第一学历和最高学历进行打标签。若不在院校清单中，则为（非目标院校）
3. 输出：每条简历新增第一学历和最高学历的两个字段。根据学历打标签的简历清单

# 第四步：需求录入
1. 输入：校招需求汇总表
2. 输出：结构化的需求表

# 第五步：简历分配
1. 输入：简历库+需求表+接口人清单
2. 筛选逻辑：
	1. 状态为待处理的简历
	2. 第一志愿简历
	3. 符合目标院校
3. 分配逻辑：
	1. 按照部门进行简历分配，分配数量为最大HC的5倍（可配置）
	2. 分配原则：
		1. 志愿优先
		2. 专业匹配
		3. 若相同或相似岗位对外发布只有一个，简历分配原则：根据需求数量在同类型的简历中同比例分配
4. 分配执行：下发至二层部门接口人
