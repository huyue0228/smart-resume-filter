# 智能简历筛选系统 · 工作流与排期

> 目标：2026-07-31 交付一套内网部署的校招简历处理系统 · 单批次约 3 万条 · 规则 + LLM 可配置

---

## 一、整体工作流

```
  上传简历库          ┌──────────────────── 5 步流水线 ────────────────────┐
  (表格+原始文件) ──► │ ① 查重排序 → ② 岗位分类 → ③ 院校分类 → ④ 需求录入 │ ──► ⑤ 简历分配 ──► 下发接口人
                      └─────────────────────────────────────────────────────┘
        每步：异步执行 + 进度 → 结果预览 → 人工微调 → 导出
```

---

## 二、每步做什么 · 产出什么

| 步骤 | 输入 | 做什么 | 产出 | 智能点 |
|---|---|---|---|---|
| **① 查重 + 志愿排序** | 简历库 + 省份南北映射 | 按「姓名+手机号」识别同一人；主体内按投递时间标第一/二志愿；跨主体按南北规则排第一~四志愿（南→YLS、北→GW，户籍缺失看学校所在地） | 带志愿排序的投递清单 | 规则 |
| **② 岗位分类** | 简历库 + 岗位类别映射表 | 投递岗位 → 岗位类别打标签；未命中可用 LLM 模糊匹配 | 带岗位类别标签的清单 | 规则 / LLM |
| **③ 院校分类** | 简历库 + 目标院校清单 | 第一/最高学历按校名查清单打标签；**学生写简称时用 LLM 归一化识别** | 新增「第一学历/最高学历院校标签」两字段 | 规则 + **LLM 简称识别** |
| **④ 需求录入** | 校招需求汇总表 | 解析为结构化需求（部门/岗位/HC/目标院校/专业） | 结构化需求表 | 规则 / LLM 辅助 |
| **⑤ 简历分配** | 简历库 + 需求表 + 接口人清单 | 筛选(待处理∧第一志愿∧符合目标院校)；按部门分配，量=最大HC×5(可配)；志愿优先→专业匹配→同类型同比例分配 | 分配结果 + 下发二层接口人 | 规则 / LLM 专业匹配 |

**角色：** HR 管理员（全流程+配置） · 部门接口人（仅看本人分配，下载简历、标记处理状态）
